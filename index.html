工作流对接说明

评论大赛工作流对接说明

工作流1采集资讯并提交候选事件入库；工作流2根据运营选中的事件生成文章与评论角度，或生成一道题干。按 Tab 查看各自的调用参数、返回字段、配置方式与测试要求。

工作流1事件生成入库 工作流2文章与题库生成

工作流1 · 事件生成入库

业务系统传入一个采集基准日期；工作流检索该日期及前一天的公开资讯，清洗并整理为候选事件，逐事件调用入库接口。本页说明工作流级输入、最终输出及当前内置配置。

对接边界：业务系统只传 date，不传搜索词、品牌、历史 URL 或批次号。搜索配置保存在工作流节点内；技术需提供正式入库接口并发布为 HiAgent 可调用的插件。工作流负责本轮清洗、同事件整理和提交候选事件；跨批次及入库后的事件去重由业务系统处理。
01 / 工作流

工作流总览

搜索按词循环，入库按事件循环；一个事件可对应多个来源 URL，但只发起一次该事件的入库请求。

1 开始接收 date
→
2 内置配置生成搜索词、时间范围和批次号
→
3 逐词搜索豆包国内 Custom；每词调用一次
→
4 规则清洗日期、URL、品牌初筛；保留全文
→
5 AI归并判断同一事件和排除项
→
6A / 6B 入库校验模型结果；调用技术提供的入库插件
→
7 汇总结束输出处理状态与数量
正常有事件

6A 组装事件请求；6B 每事件调用一次入库插件；7 汇总返回 JSON 文本。

正常无有效事件

跳过不必要的模型或入库步骤，最终 output 是固定纯文本 无有效事件。

执行或校验失败

应走失败出口；不得把全搜索失败或模型校验失败当作“无有效事件”。

本轮同 URL 合并发生在工作流内；跨批次重复来源、不同 URL 的同一历史事件及入库后的候选事件合并由业务系统负责。工作流不查询历史库，不计算真实热度，不生成评论文章、题目或评分规则。

02 / 调用契约

工作流输入参数

业务系统调用 HiAgent 工作流时，开始节点只有一个业务字段。平台鉴权、工作流 ID 和传输层封装按实际 HiAgent 调用方式另行配置，不属于下面的业务参数。

字段类型／必填格式与作用边界
dateString／必填严格 YYYY-MM-DD，须为有效日历日期。工作流搜索该日期前一天和当天两个北京时间自然日。不要求等于实际执行日；允许补跑历史日期。节点 2 内部接收名为 run_date，调用方仍传 date。

业务输入示例：

{"date":"2026-09-29"}

该示例使节点 2 生成豆包 TimeRange=2026-09-28..2026-09-29；collected_at另记实际运行时刻。日期无效时节点 2 报错，工作流不应继续搜索。历史 URL 无需传入：本轮 URL 合并由清洗节点完成；跨批次 URL 防重和入库后事件去重由业务系统负责。

03 / 返回契约

最终输出字段

工作流结束节点只声明一个 output:String。它有两种正常内容形态，调用方必须先判断固定文案，再决定是否解析 JSON；不要把所有结果一律当 JSON。

层级字段类型含义与处理方式
End 输出outputString等于 无有效事件 时为正常空结果；否则按下面入库汇总 JSON 文本解析。HiAgent HTTP 响应可能还有平台自身包装，本表只定义工作流 End 变量。
入库汇总 JSONbatch_idString本次执行批次号，格式 YYYYMMDD-UUID；用于追踪，不是事件主键。
入库汇总 JSONstatusStringsuccess＝本分支全部成功；partial_success＝有搜索或保存错误但仍有处理结果；failed＝本分支拟保存事件均未保存。平台级异常可能没有该字段。
入库汇总 JSONsaved_event_countInteger本批新建成功的事件数；按事件计数，不按 URL 计数。
入库汇总 JSONexisting_event_countInteger入库服务判断为已存在的事件数；不计入新建。
入库汇总 JSONmessageString简短处理提示，例如“事件处理完成”；不作为机器判定依据，以 status 和计数为准。
入库汇总 JSONerrorsArray<Object>错误列表；成功可为空数组。每项固定含 stage、code，可能按错误类型附 query_id、title、urls；不要假定这些附加字段都存在。

最终 output 只用于告知批次处理结果，不返回事件列表、来源 URL 或 Markdown 正文；这些内容由逐事件入库接口保存。技术需提供业务系统的正式入库与后续查询能力。当前已验证的临时接口使用独立存储，不等于业务系统已接收这些事件。

两种正常返回示例

有事件进入入库汇总时，output 的字符串内容如下（下方展示的是解析后的内容，实际 output 仍为 String）：

{
  "batch_id": "20260929-11111111-1111-4111-8111-111111111111",
  "status": "success",
  "saved_event_count": 2,
  "existing_event_count": 1,
  "message": "事件处理完成",
  "errors": []
}

正常空结果：output 的字符串内容恰为 无有效事件，没有批次号、计数或 errors。若以工作流变量形式展示：

{"output":"无有效事件"}
接线前提：当前导出的 HiAgent 画布仍可能让 fatal=true 落入空事件的 Else 分支；固定文案节点的新代码也尚待同步。因此这里的“无有效事件”契约是设计目标，不能在修正和联调前把现有画布的该文案当作可靠成功信号。平台报错、超时或 JSON 解析失败也不能伪装为此文案。
04 / 内置配置

配置与搜索计划在工作流内部维护

开始节点不接受品牌、搜索词或过滤规则。它们写在节点 2“配置与搜索计划”的 Python 脚本里：BRAND_ROWS、QUERY_ROWS、RULES、MAX_SEARCH_REQUESTS。节点 2 运行时生成 plan:String 配置快照，后续节点 4、6A、7 读取同一份快照。plan 不含搜索结果或正文。

05 / 技术交付接口

候选事件入库接口与 HiAgent 插件

工作流在 6B 按事件循环调用一次插件：一个事件提交一个请求，该事件的多个 URL 放在同一请求的 sources 数组中。技术团队须提供业务系统的正式入库服务、接口契约及可在 HiAgent 工作流中选择的插件；现有独立临时服务只用于验证链路，不代替正式业务库。

交付项明确要求
正式业务接口提供 HTTPS POST /api/ai-content/v1/candidate-events（若业务系统使用其他路径，应同步更新 OpenAPI 与插件），JSON Body，一次保存 1 个候选事件和 1—20 个来源；只入库为“待选用”，不自动发布文章或题目。
HiAgent 插件技术提供可导入的 OpenAPI 3 契约并发布工具 save_candidate_event，在工作流中可直接选用；五个请求字段要作为插件 Body 入参，sources 必须是对象数组；四个响应字段须可供后续节点单独引用。
鉴权与容量采用服务端 Bearer 凭证，通过 HiAgent 插件安全配置，不写入工作流业务入参、Prompt 或文档。请求／响应均为 application/json；建议支持约 4 MiB 单事件请求并对超限给出明确错误，最终限额由技术确认。
查询与追溯保存事件及各来源原始 URL、标题、发布时间和完整 Markdown 正文；提供业务侧按事件查询的能力。返回稳定的业务 event_id，不能把豆包结果 ID 或批次号当事件主键。
联调交付给出正式 Endpoint、环境、鉴权配置方式、OpenAPI 文件、错误码及测试环境；插件切换正式地址后，完成创建、重复、冲突、多 URL、异常及工作流最终汇总的联调。

请求 Body：单事件，多来源

字段类型／必填约束与含义
batch_idString／是YYYYMMDD-UUID；同轮事件共用。日期前缀对应开始节点 date，单事件重试沿用原值。
collected_atString／是带时区 ISO 时间；本轮实际采集开始时刻，不用于决定搜索窗口。
titleString／是事件标题，1—200 字符。
summaryString／是事实概述，接口允许 1—500 字符；工作流生成目标通常不超过 200 字。
sourcesArray<Object>／是1—20 个来源；一个来源对象仅对应一个 URL 和其正文。不要把多个 URL 拼入同一个字符串。
sources[].urlString／是单个 HTTP(S) 原始 URL，最长 4096 字符；服务端负责规范化及历史防重。
sources[].titleString／是原始来源标题，1—500 字符。
sources[].published_atString／是带时区 ISO 发布时间；按 batch_id 日期前缀核验为前一天或当天，且不得晚于 collected_at。
sources[].contentString／是该 URL 对应的原始 Markdown 正文，1—100000 字符；不是 AI 输入的前 800 字截取。
sources[].search_queriesArray<String>／是实际命中该 URL 的搜索词，去重后 1—17 条，每条 1—100 字符。
sources[].provider_idString／否豆包结果 ID，最长 256 字符；只作追溯，不作唯一键。
sources[].site_nameString／否来源站点名，最长 200 字符；没有则省略，不猜测。

统一响应：插件必须暴露四个顶层字段

字段类型契约
statusStringcreated＝本次新建；existing＝历史已存在；failed＝未保存。工作流凭该字段核对结果，不能只看 HTTP 200。
event_idStringcreated、existing 时为非空业务事件编号；failed 时为空字符串。
codeString机器可判断结果码，例如 OK、ALREADY_EXISTS、SOURCE_CONFLICT；不可只返回提示文案。
messageString简短中文说明，不含凭证、SQL 或堆栈；机器处理以 status/code 为准。
HTTPstatus／code技术侧保存结果与工作流处理
200created / OK事务提交后生成新 event_id；工作流新建计数 +1。
200existing / ALREADY_EXISTS返回原 event_id，不覆盖历史事件；工作流已存在计数 +1。
200failed / SOURCE_CONFLICT部分来源已归属历史事件或来源归属不同事件；本次不写入。工作流记录单项失败，正常响应可继续后续事件。
400failed / VALIDATION_ERROR字段、URL、时间窗口或正文不合法；不自动重试。
401failed / UNAUTHORIZED插件鉴权失败；视为明确错误，不转成“无有效事件”。
413failed / PAYLOAD_TOO_LARGE请求体超限；保留原载荷及错误供排查，不截断来源正文后静默重试。
500／503failed / INTERNAL_ERROR 或 SERVICE_UNAVAILABLE服务异常；当前工作流不配置自动重试。非 2xx 若被 HiAgent 当插件异常，需走明确失败出口。

代表性响应示例：

{"status":"created","event_id":"EVT-001","code":"OK","message":"候选事件已保存"}
{"status":"existing","event_id":"EVT-001","code":"ALREADY_EXISTS","message":"来源已入库，返回已有事件"}
{"status":"failed","event_id":"","code":"SOURCE_CONFLICT","message":"来源归属冲突，未写入"}

上面三行是三次互斥的响应示例，不是一个 JSON 数组。服务自身产生的非 2xx 应尽量返回同样四字段；网关返回非 JSON、网络超时或插件直接抛错时，工作流可能拿不到四字段，必须按失败处理，不能计为入库成功。

existing 如何判定：查来源 URL 归属，不比较全部字段

接口先把本次 sources[].url 逐一规范化，再查询业务库中的来源归属。只有本次提交的全部 URL 都已存在、且都归属于同一个历史事件，才返回 existing / ALREADY_EXISTS 和原 event_id；不新建事件，也不覆盖历史标题、摘要、正文或人工修改。请求只包含该历史事件的部分已存来源时，同样返回 existing。

历史库与本次请求响应原因／处理
历史事件 E1 已有 URL A；本次只提交 A，但标题、正文或批次号变化existing / ALREADY_EXISTS判重依据是 A 的规范化 URL 及其事件归属，不要求其他字段完全一致；返回 E1 的编号，不覆盖旧值。
E1 已有 A、B；本次只提交 Aexisting / ALREADY_EXISTS本次提交的全部来源均归属 E1；不要求与 E1 已存的来源集合完全相同。
E1 已有 A；本次提交 A 和新 URL Bfailed / SOURCE_CONFLICT部分来源已存在、部分为新来源；整次请求不写入，交由业务侧确认是否补来源。
A 属于 E1、B 属于 E2；本次提交 A 和 Bfailed / SOURCE_CONFLICT已存来源分属不同事件；整次请求不写入。
E1 已有 A；本次提交不同 URL C，即使 C 报道同一件事created / OK仅凭 URL 无法证明 C 与 E1 同事件；先新建候选，入库后的跨 URL 同事件去重／合并由业务系统处理。

URL 规范化应统一处理协议和域名大小写、默认端口、片段和已知跟踪参数，同时保留能区分文章身份的路径与查询参数；正式业务接口须公布并固定具体规则，以规范化 URL 的唯一约束和数据库事务保证并发幂等。豆包结果 ID、batch_id、标题、摘要、发布时间和 Markdown 正文都不作为 existing 的判定键。

去重责任：工作流本轮整理，业务系统处理历史与入库后合并

处理层责任与规则
工作流本次搜索的相同 URL 只保留一份来源，AI 将本轮能确认是同一事件的不同 URL 归到一个候选事件；之后逐事件提交。工作流不查询历史库，也不接受历史 URL 入参。
业务系统入库接口规范化来源 URL（保留文章身份参数），以数据库唯一约束和事务保证并发幂等；同一批来源已属于同一历史事件返回 existing，不覆盖人工修改；部分重叠或分属多个历史事件返回 SOURCE_CONFLICT 且不写入。
业务系统入库后治理不同 URL 但描述同一历史事件的跨批次语义去重、候选事件合并和人工确认均在业务系统处理。首版工作流与 URL 幂等接口不能保证识别这种重复；业务侧应保留可追溯的来源关系和处理结果。
当前与目标：阿里云临时入库插件已经跑通一次成功批次，使用独立存储和临时 event_id。技术提供正式业务接口及 HiAgent 插件后，仍需切换插件目标、确认历史数据是否迁移，并逐项验证上述响应和去重行为；不能把临时服务的成功记录当作正式业务库验收。

测试要点与当前状态

场景预期
非法日期节点 2 拒绝，不调用豆包搜索；date 与实际运行日不同可正常补跑。
同 URL 多词命中本轮只保留一个来源，同时保留命中的全部查询词；历史重复由入库服务判断。

来源部分重叠返回 failed/SOURCE_CONFLICT，本次零写入；不同 URL 的同一历史事件由业务系统后续去重／合并，不要求工作流查询历史。

字段／类型文章调用题目调用含义与格式
generation_type
String		必填：article必填：question决定生成分支；调用方只允许这两个小写值。
event_content
String		必填必填运营选中事件的相关正文与事实资料，非空。多个来源按标题、URL、正文分段保留，背景由模型从中提取；无需额外传 topic_background。首版业务侧限12,000字符，正式容量按联调结果调整。

03 / 返回契约

最终输出字段

End 只返回一个 output:String，内容为本次模型生成的 JSON 文本。调用方根据本次传入的 generation_type 选择解析规则；模型节点内的 raw_output 是内部变量，无需调用方另取。

层级／字段类型含义与使用方式
End：outputStringJSON字符串；先读取平台执行状态，再从实际平台响应中取出该字段并解析。平台可能另包一层响应对象，本页只约定End变量。
文章：article_contentString文章正文，可包含换行。标题沿用请求中的 topic_name；正文按 word_count_range 验收。
文章：comment_anglesArray<Object>评论角度数组；有效草稿的元素数量必须等于 angle_count。
角度：nameString非空角度名称，例如“夜间使用体验”，用于展示角度主题。
角度：guidanceString非空观察与讨论指引；提示成员从哪些方面思考，不是可直接提交的完整评论。
题目：stemString一道独立可读的开放式题干，10—200字。题目分类、立场、参考要点、分值和评分配置由业务系统另行维护。

资料不足与结果解析

资料不足时，模型按以下结构返回；这是没有可保存草稿的结果。业务系统展示“资料不足，请补充事件正文”，不创建空文章或空题目。

{"article_content":"","comment_angles":[]}
{"stem":""}
技术处理顺序
  1. 确认HiAgent执行成功；超时或节点错误按调用失败处理。
  2. 取End的output并解析JSON。开头换行和空格可正常解析；内容引号须正确转义，不通过时提示生成结果异常。
  3. 按请求类型校验字段、非空、正文或题干字数；文章还要核验角度数组数量及每项name、guidance。
  4. 校验通过后展示草稿，保留所选事件关联，由运营编辑确认后保存、审核与发布。

本工作流不额外生成status、event_id或created/existing状态。正文换行按文本渲染；不要把模型输出作为HTML执行。题干及文章字数按去空白后的可见字符数统计，中文、标点、数字和英文字母均计入。

04 / 配置维护

节点配置与修改方式

业务系统只传开始节点字段。搜索规则、资料整理方式和两套生成提示词维护在HiAgent内部；修改后需保存并发布工作流，再用文章和题目样本回归。

内容维护位置当前规则与修改影响
搜索问题“查询问题组装”Python读取related_model，去掉首尾空格，输出 model_query=车型名称＋" 最新资讯"。修改搜索词拼接方式需改此脚本。
搜索时间与条数豆包国内搜索插件节点TimeRange、Count由维护人员按需填写。修改这两项无需同步改Python；会影响返回内容、费用与耗时。
搜索请求格式国内搜索插件Query引用model_query；SearchType为web，ContentFormats为markdown；Filter是对象 {"NeedContent":true,"NeedUrl":true}。凭证在插件中配置。
联网资料长度“搜索结果整理”Python从有URL及正文的结果中取最多3条，每条正文前1,000字符，连同标题、URL、发布时间组成 model_material:String。此上限独立于Count；Count调大后，送AI仍最多3条，需更多资料时修改此脚本。
文章生成规则“生文大模型”Prompt逐项读取选题、事件正文、车型、字数范围、角度数量、联网资料；输出正文和角度数组。事件事实优先，车型和年款不匹配时不采用相应产品数据；正文与指引使用中文引号，保证JSON正确转义。
题目生成规则“生题大模型”Prompt只读event_content，一次生成一道10—200字题干；要求分析、回应或提出观察，避免预设宣传结论。评分相关内容不在生成范围。
分支与变量引用条件节点、变量聚合、AI输入配置有车型和空车型均产生可用的model_material；生文AI必须显式绑定该变量。两个AI的raw_output聚合后进入End的output。
维护重点：TimeRange、Count在插件节点自由配置；搜索词及资料截取规则改对应Python；写作与生题要求改对应Prompt。每项修改都需发布HiAgent工作流才会对业务调用生效，更新本说明页不会自动修改工作流。
内部变量如何流转
变量产生节点用途与下一站
model_query:String查询问题组装Python一条搜索词，绑定豆包Query。

model_material:String搜索整理或空车型资料分支联网资料文本或固定空资料说明，经变量聚合后传给文章AI；不是业务入参。
